# 阅读、索引与来源验证

先读相关任务和实际 renderer / search / AI 调用链。分块设计以
`docs/15-parent-child-chunking.md` 为入口，研究取舍见
`docs/16-chunking-research-review-2026-11-08.md`；不要把研究建议误报为已实现。

## 文档身份与定位

- Markdown 延续现有 EPUB 阅读链路；文件树描述目录结构，大纲描述当前文件标题，不能把两者混成同一层目录。
- Markdown 文件夹按文件保留身份、相对资源和进度，不为了统一展示把所有文件无边界拼成一篇正文。
- EPUB CFI / href、PDF 页码及 Markdown 文件与正文偏移遵循实际 locator 契约，读取与写入保持一致。
- 标题、图片、表格和代码的展示文本可能不同于索引原文；定位必须基于同一规范正文，不对展示字符串猜 offset。
- 来源标识、文件版本、半开跨度和文本单位须明确。源文件变化后按现有失效与重索引策略处理，不能沿用旧 offset 冒充精确引用。
- 外部链接、相对图片和跨文件跳转沿现有解析入口校验；不通过渲染事件直接改数据库或用户源文件。

## 渲染与资源

- 读取、解析、分页、搜索高亮和来源跳转分别核对消费者；修一个展示路径不等于修复了定位链路。
- 图片解码、PDF 页面与文档缓存要有容量、释放和取消归属；切书后旧任务不能继续占资源或覆盖当前内容。
- 避免按每次滚动或 Widget 重建重新解析整本书。性能调整先测量样本、耗时与内存，不只比较代码长度。
- 使用真实但非私有 EPUB/PDF/Markdown 样本覆盖本次格式边界，保留临时样本与源文件只读规则。
- 解析器 / 排版器 / widget 用例证明对应组件；离屏截图证明指定条件下的布局，不能代替真实阅读器接线。
- 真实阅读流程验证 open → navigate → 位置事件 → save → close → reopen，记录平台与样本。静默约束下缺少真实运行证据时明确保留缺口。

## 父子分块与检索

- 沿现有结构约束的分块实现检查标题、段落、列表、代码、表格和超长单元；参数由当前设计和评测决定，不在 skill 固定一组阈值。
- 父块与子块都保留来源身份和原文跨度。结构路径是辅助信息，不能仅因标题同名就合并不同文件或小节。
- `sourceText`、`retrievalText` 与最终请求包装分开；补标题、表头或生成说明不能污染原文跨度。
- 扩展父块或邻块须有相关性和预算依据；命中一个子块不代表整章都应发送。
- 去重、合并连续范围时保留文件 / 版本 / 正文单元边界；不连续或跨页证据使用多个来源，不伪造一段连续引用。
- 最终预算包含来源标签、标题、包装和正文。实际请求内容、来源快照与 UI 引用要一致，不能截断后仍展示未发送证据。
- 无命中、取消、索引未就绪和失败保持不同语义；不为了填满上下文加入无关段落或退回无界整本书。
- AI 能力与上下文范围服从当前用户要求和产品决策；本规范不额外限定或扩大 AI 能力。测试不擅自调用真实 provider 或读取用户密钥。

## 效果评测

修改检索时检查 `tool/retrieval_eval/evaluation_core.dart`、相关命名测试与样本，先复现基线再比较同一口径：

- 原文跨度与引用定位正确，命中内容确实来自该版本的源文档。
- 证据覆盖完整，尤其是跨块依赖、表头、例外条件、多文件同名标题。
- 包含无答案问题，检查错误填充、重复上下文和预算溢出；不要只统计“命中一点”。
- 在相同样本、预算和配置下比较召回、完整性、重复率与耗时；调参集和保留集区分，记录回退。
- 离线检索指标、真实模型答案质量、来源跳转和端到端延迟分别验证；单项变绿不代表整体效果提高。

只按本次变化选必要场景，不为普通文案或样式修改自动启动整套检索评测。
