# PageSage 交付协调

本入口面向单仓库 Flutter 应用，组织任务连续性、契约闭环和证据复用。先读根 `AGENTS.md`。

## 选择交付深度

| 情况 | 做法 |
| --- | --- |
| 小型样式、文案或局部行为修复 | 当前会话直接完成，选择对应验证；不强制新任务或独立会话 |
| 数据迁移、定位/持久化契约、跨模块行为或检索算法 | 使用一份任务记录，明确风险、消费者、兼容性和验证矩阵 |
| 多个独立可交付阶段或已授权的多人/多会话协作 | 记录阶段与硬依赖；确有独立交付边界才拆任务 |

按实际影响判断，不能仅按文件数或“只有一个仓库”降低数据安全要求。
不为追求更高流程级别而增加会话、审批、文档和测试。

## 交付闭环

1. “继续”或状态不清时先用 `workstream-triage`，核对现有实现、用户目标和未完成部分。
2. 在实际代码基础上写清预期行为、边界、硬依赖和关键反例。复用已有任务；必要时使用
   [任务模板](assets/task-template.md)，已有中文任务不必改格式。
3. 产品代码使用 `pagesage-dart-engineering`；契约变更使用 `api-contract-sync`；实施前用
   `validation-harness` 选定最小证明，不另设任务状态机门禁或要求自动提交文档。
4. 完成一个用户可观察的纵向切片，包括必要数据、应用逻辑、界面和验证。共享契约的硬依赖先解决。
5. 检查实际差异和受影响入口。发生失败时保留证据，集中列出已能确认的缺陷，修复后仅补受影响验证。
6. 应用变更按验证 skill 构建、安装并核对产物；指令/文档变更只验证相应结构与内容。
7. 在原任务中更新一次结果和真实缺口。完成授权范围后停止，不自行启动下一波产品工作。

## 协作与权限

日常本地开发默认当前会话实施，不强制协调者、执行者、验收者三个会话。数据迁移、
删除、索引正确性等高风险变更宜做独立复核；只有确有独立审查者时才能称为独立验收。
独立复核与普通自检须分别记录，不能以重复运行测试冒充独立性。

创建新聊天、委派、跨会话发消息、切换模型、创建分支/worktree、提交和推送遵守用户与宿主权限，
skill 本身不授权这些动作，也不要求每次重新征询已明确授予的同范围权限。

已授权协作中，一个任务保留原执行者与复核者；返修只传递缺陷、当前候选状态和最小验证。
同一路径只有一个写入者；复核基于稳定候选，不能让实现同时更改其源代码、样本或数据库。
新的独立 worktree 不会携带当前未提交改动，交接前核对接收端实际可见的代码和规范，不能为此擅自提交。

## 参考边界

本入口只维护链接的 PageSage 任务模板；工程、契约和验证规范分别读取对应 skill，
不复制另一套流程、脚本或策略配置。
