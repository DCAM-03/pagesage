# PageSage 产品需求文档

版本：0.1  
日期：2026-06-13  
状态：详细 PRD  

## 1. 背景

电子书阅读常见问题：

- 书籍分散在不同应用和文件夹里，难以统一管理。
- EPUB、PDF 的阅读体验割裂；MOBI/AZW 兼容后续再处理。
- 大量书籍内容无法快速检索。
- 划线、书签、笔记不容易沉淀和复用。
- 读到复杂段落时，用户需要离开阅读器去搜索或询问 AI。
- 很多阅读器把云同步和账号作为前置条件，用户对隐私和数据控制不放心。

PageSage 试图解决这些问题：它以本地书库为中心，把阅读、搜索、标注、笔记和 AI 问答连接在一起。

## 2. 产品目标

### 2.1 近期目标

- 让用户可以在 Android 和 Windows 上管理 EPUB 和 PDF。
- 提供稳定、可配置的阅读体验。
- 自动保存每本书的阅读进度。
- 支持书籍分类、书签、笔记和全文搜索。
- 支持在阅读中划词调用 AI。

### 2.2 长期目标

- 成为个人阅读知识库。
- 支持跨设备同步，但不强制依赖云。
- 支持更多导出格式和知识管理工具。
- 支持本地模型，减少用户对第三方 AI 服务的依赖。
- 支持 OCR、文档问答、章节总结和复习卡片。

## 3. 用户画像

### 3.1 技术书读者

特征：

- 阅读 EPUB/PDF 技术书。
- 需要搜索 API、术语、代码片段。
- 经常做笔记和摘录。
- 希望 AI 解释复杂概念。

核心需求：

- 技术书排版稳定。
- 代码块显示清晰。
- 全文搜索准确。
- AI 能结合上下文解释。

### 3.2 论文和资料读者

特征：

- 大量阅读 PDF。
- 需要按页、章节、关键词跳转。
- 需要保存引用和笔记。

核心需求：

- PDF 打开快。
- 页码跳转可靠。
- 搜索和高亮可用。
- 笔记能回跳原文位置。

### 3.3 小说和通勤读者

特征：

- 主要阅读 EPUB 或 PDF。
- 更关心舒适阅读、进度记忆、夜间模式。

核心需求：

- 字号、行距、背景可调。
- 进度自动恢复。
- 书库封面好看。
- 操作简单，不打扰阅读。

### 3.4 语言学习者

特征：

- 阅读外文书籍或双语资料。
- 需要划词翻译、解释、例句。
- 需要保存生词和笔记。

核心需求：

- 划词菜单便捷。
- AI 翻译和解释入口明显。
- 笔记可搜索、可导出。

### 3.5 知识管理用户

特征：

- 读书后会整理到 Obsidian、Logseq、Notion 或 Markdown 文件。
- 重视数据导出和可迁移性。

核心需求：

- 笔记可导出 Markdown。
- 书签、划线、AI 回答能沉淀。
- 数据默认本地保存。

## 5. MVP 范围

MVP 目标是形成基础阅读闭环。

必须包含：

- Flutter 项目可以在 Android 和 Windows 运行。
- 书库页面。
- 导入 EPUB。
- 导入 PDF。
- 打开 EPUB 阅读。
- 打开 PDF 阅读。
- 自动保存阅读进度。
- 重新打开书籍恢复进度。
- 基础阅读设置：
  - 字号
  - 背景
  - 明暗主题
- SQLite 持久化：
  - books
  - reading_progress
  - settings

MVP 可以暂缓：

- MOBI/AZW 与 Calibre 转换。
- AI 问答。
- 全文搜索。
- 划线笔记。
- Markdown 导出。

## 6. Alpha 范围

目标是补齐完整阅读管理能力。

包含：

- 分类目录。
- 标签。
- 书签。
- EPUB 目录。
- PDF outline 或页码目录。
- 书内搜索。
- 笔记。
- 划线。
- 全文索引。
- 全局搜索。
- 搜索结果跳转。

## 7. Beta 范围

目标是补齐智能能力和导出能力。

包含：

- AI Provider 设置。
- 划词 AI 问答。
- AI 回答保存为笔记。
- 笔记导出 Markdown。
- AI 请求隐私确认。

后续单独评估：

- MOBI/AZW 导入。
- Calibre `ebook-convert` 转换。

## 8. v1.0 范围

目标是达到可长期使用和公开发布的稳定度。

包含：

- Android 打包。
- Windows 打包。
- 错误恢复。
- 数据备份和恢复。
- 任务中心。
- 快捷键。
- 辅助功能。
- 性能优化。
- 常见 EPUB/PDF 样本兼容性测试。

## 9. 非目标范围

首版明确不做：

- 账号注册登录。
- 云书库。
- 云同步。
- 在线书城。
- DRM 破解。
- 扫描版 PDF OCR。
- 多人协作批注。
- 社区评论。
- 自动上传整本书做 AI 分析。
- 浏览器 Web 版完整阅读器。
- MOBI/AZW 导入与 Calibre 转换。

## 10. 成功指标

MVP 成功指标：

- EPUB 和 PDF 可以稳定导入、打开、关闭、恢复进度。
- Android 和 Windows 两个平台都可运行。
- 10 本测试书籍连续打开不崩溃。
- 阅读进度保存成功率接近 100%。
- 常规 EPUB 首屏打开小于 2 秒，常规 PDF 首屏打开小于 3 秒。

Alpha 成功指标：

- 书签、笔记、分类数据重启后不丢失。
- 全局搜索可以命中正文、笔记、书签。
- 搜索结果点击后能回到原文位置。
- 1000 条搜索 chunk 查询在可接受时间内返回。

Beta 成功指标：

- AI 请求可取消。
- AI 回答可保存并被搜索。
- 用户可以关闭所有联网 AI 功能。

## 11. 业务规则

### 11.1 导入规则

- 同一个文件重复导入时，通过 hash 识别。
- 重复导入时提示：
  - 打开已有书籍
  - 仍然导入副本
  - 取消
- 导入文件默认复制到应用私有书库目录。
- 原文件路径可记录，但不依赖原文件存在。

### 11.2 删除规则

- 从书库移除：删除应用内记录和副本，不删除用户原始路径文件。
- 删除全部数据：删除应用副本、封面、索引、书签、笔记、AI 记录。
- 危险删除必须二次确认。

### 11.3 进度规则

- 一本书只有一个主阅读进度。
- 打开书籍默认恢复主进度。
- 用户可以从头开始阅读，但不删除历史书签和笔记。
- 标记已读会把 progress 设置为 1.0。

### 11.4 AI 规则

- 未配置 AI 时，划词菜单仍显示其他操作，AI 操作进入配置引导。
- AI 请求只发送用户选中文本和用户允许的上下文。
- 默认不发送整本书。
- API Key 不写入普通日志。

## 12. 隐私要求

默认行为：

- 书籍文件保存在本机。
- 笔记和进度保存在本机。
- 不需要账号。
- 不自动同步。
- 不自动上传书籍正文。

必须提供：

- 关闭 AI 功能的开关。
- 每次 AI 请求前确认上下文的选项。
- 清空 AI 对话历史的入口。
- 删除所有本地数据的入口。

## 13. 平台差异要求

Android：

- 支持系统文件选择器。
- 支持返回手势。
- 支持竖屏优先，平板适配横屏。
- 阅读器工具栏默认自动隐藏。

Windows：

- 支持窗口缩放。
- 支持键盘快捷键。
- 支持右键菜单。
- 支持拖拽导入，后续实现。
- 支持三栏布局。

iOS/macOS/Linux：

- 后续支持，当前规格需要避免写死 Android 或 Windows 专属业务模型。
