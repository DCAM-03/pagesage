# PageSage 现代化 UI/UX 重设计方案

版本：0.1  
日期：2026-07-03  
状态：设计改造规划  

## 1. 背景

PageSage 当前已经具备书库、导入、阅读器、进度、搜索、笔记、标注、AI 和导出等核心能力，但界面仍偏向 Flutter 默认控件拼装。主要问题不是单个颜色或圆角，而是产品体验缺少统一视觉语言、清晰信息层级、现代桌面效率和移动端沉浸感。

本方案用于启动一次 UI/UX 现代化改造。改造前先明确目标、范围、验收和阶段，避免在后续实现中只做零散换皮。

## 2. 设计目标

PageSage 应呈现为一款安静、现代、专业、适合长期使用的本地优先阅读和知识沉淀工具。

目标效果：

- 第一眼不再像 Flutter 默认 Demo。
- 书库像现代本地知识库，而不是普通文件列表。
- 阅读器让正文和 PDF 页面成为绝对主角。
- 桌面端具备生产力工具质感，支持高效筛选、面板和快捷键。
- 移动端保持单手友好、沉浸阅读和底部抽屉模式。
- AI 功能清晰、克制、透明，明确每次发送的上下文范围。
- 空、加载、错误、索引中、AI 未配置、PDF 无文本层等状态都有明确反馈。
- 长标题、长标签、长路径、小屏幕和高对比模式不破坏布局。

## 3. 设计原则

### 3.1 阅读优先

阅读器中正文、PDF 页面、选中文本和当前位置是最高优先级。工具栏、状态栏、AI、Notebook、搜索和设置只能作为上下文工具出现，不长期遮挡内容。

### 3.2 低噪声、高密度

桌面端允许更高信息密度，但不堆叠卡片、不滥用 Chip、不把每个区块都做成浮动容器。移动端减少同时出现的控制数量，用底部抽屉承载复杂操作。

### 3.3 本地优先可见

导入、索引、备份、删除、AI 请求都要让用户知道数据在本地如何流动。AI 入口必须展示上下文范围，不暗示会自动理解整本书。

### 3.4 常见控件优先

工具按钮使用图标按钮，模式选择使用分段控件，筛选使用菜单或可清除 filter chips，数值设置使用滑块或输入框，危险操作使用确认对话框。

### 3.5 平台适配

Android 优先触摸、返回手势和沉浸阅读；Windows 优先导航侧栏、快捷键、右键菜单、可调整面板和窗口缩放。

### 3.6 可访问性不是收尾项

颜色不能作为唯一状态表达；图标按钮需要语义和 tooltip；焦点必须可见；长文本必须可省略或换行；高对比主题必须可读。

## 4. 外部设计参考

本次规划参考以下公开设计系统和 UX 原则，并结合 PageSage 的阅读器场景取舍：

- Material Design 3：自适应导航、颜色角色、状态层和组件一致性。
- Microsoft Fluent 2：Windows 桌面生产力工具、导航结构、列表密度和命令体验。
- Apple Human Interface Guidelines：排版、信息层级、平台一致性和内容优先。
- Nielsen Norman Group AI UX：用户控制、透明度、错误恢复和 AI 能力边界。

## 5. 信息架构目标

### 5.1 主导航

主导航保留 5 个核心入口：

- 书库。
- 搜索。
- 笔记。
- 任务。
- 设置。

任务中心从设置里的深层入口升级为主导航的次级核心入口，因为导入、索引、导出和备份都是本地优先产品的重要可见状态。

### 5.2 阅读器导航

阅读器不是主导航 Tab，而是从书籍、搜索结果、书签、笔记和 AI 记录进入的沉浸工作区。

阅读器内部的信息结构：

- 中央：EPUB 正文或 PDF 页面。
- 左侧：目录，桌面可常驻，移动端为底部抽屉。
- 右侧：上下文面板，包含搜索、Notebook、AI。
- 底部：当前位置、进度、缩放或字号状态。

### 5.3 Notebook

Notebook 是阅读中沉淀内容的统一入口，聚合：

- 书签。
- 标注。
- 摘录。
- 手写笔记。
- AI 问答记录。

Notebook 条目应按书内位置、更新时间和类型过滤，支持跳回原文。

## 6. 页面改造目标

### 6.1 App Shell

目标：从默认导航改造成现代工具外壳。

桌面：

- 左侧侧栏支持图标、标签、当前选中态和任务状态提示。
- 顶部命令区显示当前页面标题、全局搜索、导入、任务状态。
- 阅读器 route 隐藏主导航。

移动：

- 主页面使用底部导航。
- 阅读器隐藏底部导航。
- 页面顶部标题区更轻，不使用过重 AppBar。

### 6.2 书库

目标：让用户快速看到最近阅读、书籍状态和可执行操作。

桌面布局：

- 左侧分类和系统筛选。
- 中间网格、列表或紧凑列表。
- 右侧书籍详情。

移动布局：

- 顶部搜索和导入。
- 默认网格。
- 筛选使用横向 chips 或底部筛选面板。

视觉要求：

- 封面比例固定为 2:3。
- 进度用细线表达。
- 格式角标低噪声。
- 索引失败、待索引、导入中使用状态 chip 和 tooltip。
- 空状态只保留一个主动作：导入 EPUB/PDF。

### 6.3 阅读器

目标：正文优先，工具按需出现。

EPUB：

- 默认行宽在桌面约 720 到 860。
- 正文边距、行高、段距由阅读设置控制。
- 标注和搜索高亮低饱和。
- 选中文本后显示上下文浮层。

PDF：

- 页面居中。
- 缩放、适宽、页码、搜索集中在紧凑工具栏。
- 无文本层时搜索和划词入口禁用，并说明原因。

桌面：

- 左目录和右上下文面板可调整宽度。
- 底部状态栏显示章节、页码、百分比、缩放或字号。

移动：

- 默认隐藏工具栏。
- 点击正文空白处显示顶部和底部控制。
- 面板使用底部抽屉或全屏临时页。

### 6.4 搜索

目标：从简单列表升级为本地知识检索界面。

要求：

- 搜索输入置顶。
- 类型筛选使用分段控件或清晰 filter chips。
- 结果按书籍、正文、Notebook、AI 分组。
- 每条结果显示来源书籍、位置、片段和命中高亮。
- 桌面端支持右侧预览，移动端点击进入详情。
- 搜索结果可复制、保存为笔记、跳回原文、对片段提问。

### 6.5 笔记与 Notebook

目标：笔记页和阅读器内 Notebook 使用同一内容模型和视觉语言。

要求：

- 左列表、右预览的桌面布局。
- 移动端列表进入详情。
- 条目显示类型、来源、位置、摘要、更新时间。
- 编辑区和预览区分开，不把所有字段堆进弹窗。
- 跳转原文是一级操作。

### 6.6 AI 面板

目标：AI 是上下文工具，不是聊天噱头。

结构：

- 选中文本摘要。
- 上下文范围。
- 快捷动作。
- 用户问题输入。
- 回答区。
- 复制、重试、取消、保存为笔记。

规则：

- 默认上下文为“仅选中文本”。
- 发送前能看到会发送的范围和长度提示。
- AI 未配置时给出配置入口，不崩溃。
- 上下文过长时提示缩小范围。
- 回答保存后进入 Notebook 和搜索索引。

### 6.7 设置与任务中心

设置目标：

- 分组清楚，移动端使用二级页面，桌面端使用左分组右详情。
- AI、隐私、导出与备份分区明确。
- 危险操作集中到隐私与数据区。

任务中心目标：

- 导入、索引、导出、备份、恢复都可见。
- 当前任务状态可从主导航或顶部命令区看到。
- 失败任务可重试。
- 取消任务需要真正停止可取消流程并清理临时文件。

## 7. 现代化阶段

### 阶段 0：设计文档和设计系统

交付：

- `docs/08-ui-ux-redesign-plan.md`
- `docs/09-design-system.md`
- `docs/tasks/ui-ux-modernization.md`
- `docs/testing-ui-ux-checklist.md`
- 更新交互规格、视觉规范、路线图和任务索引。

验收：

- 所有目标、范围、测试、最终效果可从文档追溯。
- 不改业务代码。

### 阶段 1：设计系统与 App Shell

交付：

- 主题 token 落地到 Flutter theme。
- 桌面侧栏和移动底栏统一。
- 顶部命令区。
- 页面标题区和基础状态组件。

验收：

- 主页面在 compact、medium、expanded 下无重叠。
- 阅读器 route 不显示主导航。
- 浅色、暗色、高对比可读。

### 阶段 2：书库现代化

交付：

- 书籍卡片、列表、紧凑列表重做。
- 左侧分类和右侧详情重做。
- 空状态、导入状态、索引状态重做。

验收：

- 书库能快速识别最近阅读、格式、进度、分类、标签和索引状态。
- 长标题、无封面、索引失败、多标签不撑破布局。

### 阶段 3：阅读器沉浸体验

交付：

- EPUB/PDF 工具栏、状态栏、面板重做。
- 文本选择浮层重做。
- 阅读设置面板重做。

验收：

- 正文不被常驻工具遮挡。
- 桌面可用三栏工作区。
- 移动端底部抽屉可完成目录、搜索、Notebook、AI。
- 改字号或缩放后位置不明显丢失。

### 阶段 4：搜索、Notebook 和 AI

交付：

- 搜索页结果分组和预览。
- Notebook 统一条目视觉。
- AI 面板上下文透明化和错误状态重做。

验收：

- 搜索结果可扫描、可跳转、可提问。
- AI 发送前上下文范围清晰。
- 回答可保存为笔记并进入 Notebook。

### 阶段 5：设置、任务、可访问性和发布收尾

交付：

- 设置页分组重做。
- 任务中心主导航入口和状态提示。
- 键盘、焦点、语义和高对比修复。
- 发布截图和 UI 验收记录。

验收：

- 主要路径可键盘完成。
- 屏幕阅读器可读出主要操作。
- 发布包截图符合新版视觉。

## 8. 测试策略

每个 UI/UX 阶段完成时至少验证：

- `dart format .`
- `flutter analyze`
- `flutter test`
- Windows 1440px、1024px、768px 截图检查。
- Android 手机 360px 宽度检查。
- 浅色、暗色、护眼、高对比主题检查。
- 真实 EPUB 和 PDF：导入、打开、阅读、保存进度、重启恢复。
- 边界状态：无封面、长标题、多标签、索引失败、AI 未配置、PDF 无文本层、损坏文件。
- 键盘：Tab、Esc、方向键、Ctrl+F、Ctrl+Shift+F、Ctrl+B、Ctrl+G。
- 可访问性：tooltip、semantic label、焦点可见、文本对比度。

详细清单见 `docs/testing-ui-ux-checklist.md`。

## 9. 非目标

本次 UI/UX 现代化不引入：

- 云同步。
- 账号系统。
- 在线书城。
- MOBI/AZW 或 Calibre 集成。
- DRM 绕过。
- 扫描版 PDF OCR。
- 协作批注。
- 浏览器 Web 完整阅读器。

## 10. 完成定义

UI/UX 现代化最终完成需要满足：

- 新设计系统已落地到核心 Flutter theme 和公共组件。
- 书库、阅读器、搜索、笔记、AI、设置、任务中心均使用新版视觉语言。
- compact、medium、expanded 响应式验收通过。
- 浅色、暗色、护眼、高对比主题验收通过。
- Windows 和 Android 至少各完成一次真实 EPUB/PDF 阅读闭环验证。
- 可访问性清单无阻塞项。
- 发布截图、隐私说明、许可说明与新版界面一致。
