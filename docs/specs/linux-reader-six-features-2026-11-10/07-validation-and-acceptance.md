## 1. 验收方式与证据边界

六项作为一个交付批次，按 [总规格的 S0–S7](README.md) 连续实施，最终集中提交本表，不逐项停下来要求用户决定下一步。必要的测试、真实样本、构建和安装在实施过程中完成；未获授权的外部付费调用、系统依赖安装和可见窗口操作不能靠文档默认取得权限。

“统一验收”不等于只在最后才检查代码。每个可观察切片先自测、修复，再继续；最后回归共享链路，记录剩余缺口。没有真实独立审查者时只称自检，不称独立验收。

| 状态 | 可用证据 | 不可替代的证明 |
| --- | --- | --- |
| 已规划 | 本目录规格、契约和用例 | 不代表代码存在 |
| 已实现 | 稳定候选源码、受影响消费者齐全 | 不代表测试/真实场景通过 |
| 自动验证通过 | 命名测试、真实临时 SQLite、离屏 Widget | 不代表真窗口/真模型/真 OCR 质量 |
| 真实能力通过 | 指定 Linux 构建+样本+引擎或模型运行 | 不能推断 Windows/Android |
| 已安装 | 当前源码构建退出 0、完整 bundle 与安装一致 | 不代表运行中旧进程已更新 |
| 用户验收 | 用户按联合清单检查并给出结论 | 不用代理人自评冒充 |

以上限制只适用于 2026-11-10 首次编写规格的文档规划阶段。后续实施按本文件第 3、7 节执行验证和安装；历史证据不能代替对应源码候选的新验证。

## 2. 统一样本与冻结规则

拟在 `test/fixtures/reader_six_features/` 保存可公开的小型合成/许可样本，在 `docs/eval/reader-six-features/` 保存 manifest、配置摘要和脱敏结果。大性能样本通过生成器及固定 seed 复现，避免把大二进制塞进仓库。

| 样本集 | 最低内容 | 用途 |
| --- | --- | --- |
| `folder-basic` | 三级目录、至少 12 个 md/markdown、同名标题、相同正文副本、空文件、中文/空格路径、图片相对路径 | F1 树/大纲、重锚、资源、改名/删除 |
| `folder-events` | 原子保存脚本、同 size/mtime 替换、目录移动、watch 故障注入、慢 parse | F1 竞态和降级；脚本在现有会话静默运行 |
| `source-locators` | EPUB 重复段落、Markdown 前文插入、PDF 同页多标题/旋转/CropBox | 来源精度和旧 locator |
| `search-60` | 60 条题：开发 20/留出 40；中文长短词/单字、中英、过滤、全半角及无结果 | F4 基线与改进比较 |
| `ai-72` | 72 题：开发 24/留出 48；留出可答 32/不足 16，覆盖 EPUB/MD/PDF 和跨段推理 | F2 检索/拒答/最终答案 |
| `diagrams` | 支持语法至少 24 例，不支持/攻击/超限至少 12 例 | F5 parser/布局/语义与回退 |
| `ocr-30` | 英文清晰 10、简中清晰 10、混合/版式/旋转 5、退化/空白 5 | F6 文本质量、框、性能和失败 |
| `schema-v7` | 按真实 v7 DDL 建库，含进度/批注/笔记/parent-child/AI v1/OCR/设置 | 全链升级与旧数据保真 |
| `load-10k` | 10,000 chunks、至少 1,000 万 UTF-16 正文单位；另有 2,000 文件/接近 64 MiB 目录 | F1/F4 性能边界 |

manifest 字段：sampleId、生成 seed/来源许可、内容 SHA-256、格式、预期来源地址/页、UTF-16 精确 span、开发/留出分组、gold 引用及可答性理由。检索与搜索题的 gold 需定位到来源文本，不能只写书名。

AI 的开发/留出按完整来源文档分组隔离，不把同书相邻段分别放两组。留出题冻结后不得据失败题调整规则再报同一批留出通过；需要优化时保留失败结论，另准备未见留出验证。搜索和 OCR 同样记录调参使用过哪些样本。

### 3.1 真实 SQLite 升级

至少覆盖新建 v12、v7→v8→v9→v10→v11→v12、各中间版本→v12；历史结构由对应 DDL/fixture 生成，不在最新结构上只降低 user_version。

必须断言：

- 旧进度、选中文本、批注关联、noteId/threadId、AI 原文、来源 v1、OCR 旧框、原始设置全部保留。
- 外键/应用关联、unique、FTS 两路 trigger、旧索引引导、新 generation 指针一致。
- 同一个文件库关闭/重开后状态一致；每个迁移/发布/journal 边界故障后可恢复。
- schema 升级事务失败不留下半表或错误 user_version；secure-store pending 能独立恢复。
- 恢复备份后 profile UUID 重映射，不绑定本机残留密钥；源文件夹不写入，任务不自动跑。
- 删书后无 source、generation、term、OCR orphan；历史是否保留依现有用户删除选项，不擅自改变产品删除语义。

### 3.2 最小命令顺序

实施时按实际变更选择命名测试，默认并发 4。先最小失败场景，再相关调用方；生成/格式/分析最后汇总。以下为执行模板，不是本轮运行记录：

```bash

```

仅 schema/生成输入变化时运行生成器；依赖变化才 pub get。全套测试用于 S7 明确的整批回归，不要求每个小调整重复跑全仓。失败保留退出状态与日志；首个决定性失败先修复，再补受影响验证。

| F4 规模 | 10k chunks/1,000 万 UTF-16；warm P95 ≤ 300 ms、cold ≤ 1 s，额外索引 ≤ 原 UTF-8 正文 10 倍 |
| F2 检索 | 32 道可答题的 top5 来源窗口包含全部必需 gold 的题数 ≥ 29；同时报告单 span Recall，不能只用一个子问题命中算整题通过 |

## 6. UI 与人工检查

离屏截图至少覆盖 1024×768、1440×900、窄面板以及 150% 字号，明/暗两种阅读主题。人工逐图检查：

- 文件树选中只表示当前文件，大纲只表示当前文件标题；刷新不切页签。
- 配置名与模型可区分，未保存/测试/失败/迁移状态有文字；秘密不出现在截图。
- 搜索 exact/related、失效来源、索引中和错误不同，中文高亮不漂移。
- AI 来源/不足/生成中/未完成不混成一种绿标记，不永久盖住阅读内容。
- 图形的箭头、label、按钮、源码入口可读；不把支持范围之外的图画成不完整成图。
- OCR 进展不是黑色常驻横幅，当前阶段/失败/暂停/部分完成都可辨，取消按钮可达。
- 键盘焦点、tooltip、语义标签和对比度延续设计系统，不只靠颜色。

需要真实窗口才能证明的打开/滚动/选区/重开/页框行为待授权并在 Linux 实际样本中验证；不偷偷启动 desktop integration_test 或新应用窗口。Windows/Android 本批标待验证，不要求用户为本批补当前不便的设备。
