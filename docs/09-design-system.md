# PageSage 设计系统

版本：0.3  
日期：2026-10-20  
状态：与 `lib/app/theme/app_tokens.dart` 对齐的冻结稿  

## 1. 设计语言

PageSage 的设计语言是：安静、清晰、专业、耐用。界面应像长期使用的阅读工作台，而不是营销页、游戏化工具或传统文件管理器。

视觉关键词：

- 内容优先。
- 低噪声。
- 稳定布局。
- 温和对比。
- 桌面高效。
- 移动沉浸。
- AI 克制。
- 中性灰阶 + 电蓝点缀（2026-10 修订）：壳层保持中性，电蓝只用于选中、主按钮和链接。

## 2. Token 命名

实现时应优先用语义 token，而不是在页面中直接写颜色和尺寸。

Token 层级：

- `AppColors`（`lib/app/theme/app_tokens.dart`）
- `AppSpacing`
- `AppRadius`
- `AppDurations`
- `ReaderThemePreset`（阅读主题，与应用壳层色可分离）

实现约束：`ColorScheme` 在 `AppTheme._scheme` 中逐项显式构造，**不要换回 `ColorScheme.fromSeed`**。种子派生会把 surface 系列染上蓝紫灰，在大面积壳层上显脏，而品牌色只需要出现在选中、主按钮和链接。

规则：

- 主色不应大面积铺满页面。
- 同一页面最多一个高强调主按钮。
- 不使用大面积装饰渐变铺底（图标/品牌图除外）。
- 状态必须同时用文本或图标表达，不只依赖颜色。
- WCAG AA：主文字对比 ≥ 4.5:1（由 `test/app/theme/app_theme_contrast_test.dart` 守门）。

### 3.2 桌面 chrome

- 顶部 `AppCommandBar`：左侧显示品牌名 `PageSage`（弱化），右侧为全局搜索/导入/任务；**页面标题由 `AppPageHeader` 承担**，避免双标题。
- 左侧导航：选中项用 `accentSubtle` + 主色指示条。
- 侧栏 `AppSidePanel`：细边框、紧凑标题区。
- 不使用大面积渐变、装饰光球、彩色背景块。
- 状态必须同时用文本或图标表达，不只依赖颜色。

## 4. 排版

### 4.1 UI 字体

使用系统字体：

- Windows：Segoe UI，中文回退 Microsoft YaHei UI。
- Android：系统 sans，中文回退系统中文字体。

### 4.2 字号

| Token | 大小 | 行高 | 用途 |
| --- | --- | --- | --- |
| `labelSmall` | 12 | 16 | 角标、辅助信息 |
| `labelMedium` | 13 | 18 | 状态、meta |
| `bodySmall` | 14 | 20 | 次级正文 |
| `bodyMedium` | 16 | 24 | 默认正文 |
| `titleSmall` | 16 | 22 | 卡片标题 |
| `titleMedium` | 18 | 24 | 面板标题 |
| `titleLarge` | 22 | 30 | 页面标题 |
| `displaySmall` | 28 | 36 | 空状态主标题，少用 |

规则：

- 不用 viewport width 动态缩放字体。
- 页面内大标题必须克制。
- 工具栏、卡片、侧栏中不使用 hero 级字号。
- 中文和英文混排保持 0 字距，不使用负字距。

### 4.3 阅读排版

EPUB 默认：

- 字号：18。
- 行高：1.7。
- 段距：0.75em。
- 桌面最大行宽：720 到 860。
- 移动左右边距：20。

PDF 默认：

- 适合宽度。
- 页面间距：16。
- 外侧背景使用阅读主题背景。

| `radius.xs` | 3 | 进度条、小标 |
| `radius.sm` | 4 | 小按钮、标签 |

- 页面区块优先用布局和分割线，不默认加 Card。

## 7. 阴影和层级

| 层级 | 用途 | 样式方向 |
| --- | --- | --- |
| 0 | 页面、普通列表 | 无阴影 |
| 1 | 悬浮工具栏、菜单 | 极轻阴影或边框 |
| 2 | Dialog、底部抽屉 | 明确浮层 |

规则：

- 桌面工具面板主要靠边界和背景区分。
- 移动底部抽屉可以使用轻阴影。
- 不用厚重 elevation 制造现代感。

## 8. 组件规范

### 8.1 按钮

类型：

- Primary：导入、保存、发送。
- Secondary：重试、打开位置、重建索引。
- Text：取消、清除、低风险操作。
- Icon：工具栏操作。
- Danger：删除、清空、覆盖恢复。

规则：

- Danger 不作为默认焦点。
- Icon button 触控区域至少 48 x 48。
- Icon button 必须有 tooltip 和 semantic label。
- 复杂页面中主按钮不超过一个。

### 8.2 输入框

搜索框：

- 左侧搜索图标。
- 右侧清空按钮。
- 桌面可显示快捷键提示。
- 输入后 250ms debounce。

笔记输入：

- 标题和正文分离。
- 正文支持 Markdown 文本。
- 有来源时显示可折叠原文。

AI 输入：

- 支持多行。
- 默认 Ctrl+Enter 发送。
- Enter 换行，避免误发送长问题。

### 8.3 菜单

菜单项：

- 图标。
- 文本。
- 可选快捷键。
- 禁用原因。

规则：

- 危险项分组到底部。
- 长菜单分组。
- 禁用 AI 操作时显示“配置 AI 后使用”。

### 8.4 Filter Chips

规则：

- 只用于当前已应用的筛选或少量类型切换。
- 大量筛选放入菜单或筛选面板。
- 可清除筛选必须有明确关闭按钮。

### 8.5 卡片

卡片仅用于重复内容项：

- 书籍。
- 搜索结果。
- 笔记。
- Notebook 条目。
- 任务。

不用于：

- 页面整体区块。
- 卡片内部再放卡片。
- 设置页每个小区域都套 Card。

## 9. 核心组件目标

### 9.1 Page Header

用途：主页面标题区。

内容：

- 页面标题。
- 简短状态，如书籍数量。
- 主操作，如导入。
- 次级操作菜单。

规则：

- 移动端高度紧凑。
- 桌面端可与顶部命令区合并。

### 9.2 Command Bar

桌面使用。

内容：

- 全局搜索。
- 导入。
- 当前任务状态。
- 快捷操作。

规则：

- 不替代页面标题。
- 不放危险操作。

### 9.3 Side Panel

用途：

- 分类。
- 书籍详情。
- 阅读器目录。
- 阅读器上下文面板。
- 设置分组。

规则：

- 可调整宽度的面板保存宽度偏好。
- 最小宽度 280，最大宽度 520。
- 面板标题、关闭、Tab 清晰。

### 9.4 Empty State

结构：

- 小图标或轻插画。
- 一句状态。
- 一个主动作。
- 可选一个次动作。

规则：

- 不写大段说明。
- 不展示未支持路线，如 MOBI/AZW 或 Calibre。

### 9.5 Status Banner

用途：

- 索引失败。
- PDF 无文本层。
- AI 未配置。
- 网络失败。

结构：

- 图标。
- 简短原因。
- 可执行操作。

## 11. 响应式

| 断点 | 宽度 | 策略 |
| --- | --- | --- |
| compact | < 600 | 单列、底部导航、底部抽屉 |
| medium | 600 - 1023 | 可选双栏、侧边抽屉 |
| expanded | >= 1024 | 左导航、主内容、右上下文 |

规则：

- 固定格式控件需要稳定尺寸，避免 hover 或动态文字导致布局跳动。
- 长文本必须 maxLines + overflow 或换行。
- 移动端触控目标不小于 48。

## 12. 可访问性

最低要求：

- WCAG AA 对比度。
- 所有图标按钮有 semantic label。
- 不熟悉图标有 tooltip。
- 焦点可见。
- Tab 顺序符合视觉顺序。
- 弹窗打开后焦点限制在弹窗内。
- 状态不用颜色单独表达。
- 支持减少动画。
- 高对比主题覆盖应用和阅读器。

## 13. 动效

| 动效 | 时长 |
| --- | --- |
| 面板展开 | 150 - 200ms |
| 菜单/浮层进入 | 100 - 150ms |
| 阅读器工具栏显隐 | 120 - 180ms |
| Hover 状态 | 80 - 120ms |

规则：

- 动效不影响阅读。
- 减少动画开启时使用即时切换或极短过渡。
- 书籍卡片 hover 不位移，只改变背景或边框。

## 14. AI 视觉规范

AI 使用低频强调，不做强烈科技风。

要求：

- AI 图标和标签使用 `ai` 或 `accent`，不使用大面积紫色渐变。
- 上下文范围比回答输入更靠上，优先被看见。
- 回答区采用普通阅读文本排版。
- 错误状态给出原因和下一步。
- 取消后保留已生成内容，由用户决定是否保存。

### 14.1 AI 侧栏的容器层级（2026-10-21 改版）

侧栏只有一列宽 280–520，容器的层数必须压到最低。改版前同一屏里同时出现
标签胶囊、上下文卡片、下拉框、元信息 chip、动作 chip 五层边框，实测读者反馈
「框框太多」。现行规则：

- **标签栏不套胶囊。** 「搜索 / 笔记 / AI」与「提问 / 历史」都是底部一条细线
  （`outlineVariant` 0.6–0.9），选中项是贴在细线上的 2px `primary` 横线。
  两个标签栏直接上下相邻，各自做成胶囊会形成胶囊套胶囊。
- **上下文块不是卡片。** 标题行（`privacy_tip_outlined` + 「将发送的文本」）、
  范围选择、引用列表共用侧栏底色，靠间距和字重分层，不画底色、不画圆角边框。
- **范围选择器只在文字下画一条线。** 范围名只出现一次，就在这个控件里；
  不再在标题旁另放一个同名 chip。没有书名文件时，读文件的范围项置灰。
  控件是 `PopupMenuButton`，键盘可达，语义标签固定为「上下文范围」。
- **被截断的引用必须有展开入口。** 引用行默认显示 2–3 行并省略号截断，
  一旦真的截断（用 `TextPainter.didExceedMaxLines` 判断，不是按字数猜），
  下方给一个「显示全文 / 收起」文字链接。读者要检查的就是将要发出去的内容，
  只能看到开头等于没法检查。
- **事实用一行文本，不用 chip。** 字数、回跳位置合并成一行
  `labelSmall`：「选中文本 · 约 39 字 · 仅发送下方列表 · 回跳：第 12 页」。
- **快捷动作是文字按钮。** 「解释 / 总结 / 提炼要点 / 翻译」只是填充输入框，
  不带状态，因此不用 chip、不带图标、不加分组标题，间距压到 `x1`
  保证一行排完。
- **快捷动作只留四个，其余进「更多」。** 360px + 1.5 倍字下六个标签会折行，
  末两个独占第二行像布局出错。`docs/02-feature-spec.md` §10.3 列的
  「简单说明 / 生成问题」收进一个 `more_horiz` 图标按钮的弹出菜单，
  仍然可用，只是不占主视线。
- **回答不套底色框。** 按本节「回答区采用普通阅读文本排版」，回答直接排在
  侧栏底色上；`代码块`例外，仍有浅底，因为代码需要与正文区分。
- **编辑入口挂在标题行。** 「编辑文本」是一个图标按钮，作用于它下方的引用
  列表，不再单独占一行。
- **历史卡片保留边框。** 历史条目是重复项，按 §8.5 可以用卡片；卡内不再放
  「载入提问」（整卡可点即载入），只留复制、存笔记、跳回原文三个图标。

验收方式：`flutter test test/features/ai` 覆盖行为；视觉改动需附侧栏截图。
CJK 在 `flutter test` 默认字体下会画成空框，截图核对时需显式加载系统 CJK 字体
与 `MaterialIcons-Regular.otf`。

## 15. 实施约束

- 优先使用 Flutter Material 组件，必要时封装本地组件。
- 不引入大型 UI 包，除非明确说明 Android 和 Windows 影响。
- 设计 token 先集中，再逐页替换。
- 每次改造必须有截图或手动验收记录。
