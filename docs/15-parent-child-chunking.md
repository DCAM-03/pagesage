## 1. 决策与范围

采用「结构分层 + 顺序贪心切块 + 检索时按预算扩展」：先用小子块定位，再选择子块、局部窗口或完整父块作为上下文。章节树提供导航和额外候选，第一版不使用树路由硬过滤原有正文候选。

继续使用 Dart、Drift 和 SQLite，不引入 DuckDB、Python runtime 或整套 RAG 框架。此设计不要求向量检索；后续如接入嵌入模型，仍复用同一套块、版本与来源定位。

本地解析、切块和建树不需要调用 LLM。摘要、模型路由和联网请求是独立能力，沿用现有设置与上下文展示规则；不能因为需要建树就自动发送正文，也不据此新增「每个本地步骤都需用户确认」的规则。

本文明确替代早期讨论中的以下设想：按标题变化还原完整树、向 `search_chunks` 塞入章节行、先筛固定数量章节再检索、命中子块即无条件发送父块。

## 2. 第一版实现与剩余范围

2026-11-08 已落地 A 切片的第一版：

1. `lib/core/search/structure_chunker.dart` 先构造标题、段落、列表、代码和表格结构单元，输出带半开原文跨度的父块与子块。
2. 标题变化优先于长度上限形成父块边界；超长结构按换行、句读、空白和 Unicode 安全边界依次回退。只含标题、没有正文的中间范围不生成空父块。
3. `SearchIndexer` 将 EPUB/Markdown 的结构块映射给切块器；PDF 仍按物理页建立父块。子块仍写 `search_chunks`，父块正文写 `search_parent_chunks`，通过 `parent_id` 关联。
4. schemaVersion 5 → 6 新建父块表并添加可空 `parent_id`。旧索引保留，不猜测父块归属；重建后生成新结构。排序改为每本书内连续序号，避免 Markdown 文件夹原来的乘法编码碰撞。
5. `ContextRetriever` 用 `parent_id` 判断同父兄弟，不再用 id 尾号猜邻块。父块不超过 1600 字符时，即使同父兄弟被合并也优先发送完整父块；父块超过上限时，从同父正文中围绕命中子块截取 1600 字符窗口，保留约 180 字符前导，而不是只送子块本身或依赖“匹配靠近末尾”才补下一块。扩展仍受每书配额与最终引用上限约束。

已经由测试验证的是原文覆盖、标题边界、句读切分、emoji 安全边界、数据库迁移、父子块回读、一个人工构造的“旧 1200 字硬切丢失续文”对照样本，以及真实 PDF/Markdown 源文上的离线诊断。2026-11-08 的正确性修复补充了重复子文真实偏移、扩展跨度去重/切分、窗口首尾代理对安全、完整备选证据集合优先和实际 payload 计量；另用一本未参与调参的真实 EPUB 建立了 10 题冻结留出。尚未验证的是跨书泛化、LLM 最终回答质量、运行时重建索引、真实跳转正确率和端到端体验。

这一版仍然没有：章节树候选、索引 generation/snapshot、跨父块 `continues` 关系、表头续段关系、固定问题集人工黄金标注、嵌入检索和层级摘要。`sortOrder` 现在用于稳定阅读顺序，不作为邻接证明。PDF 没有可靠 outline 映射时仍只有页级结构。

当前长度仍是 Dart `String.length`（UTF-16 代码单元），不是 tokenizer 计数。默认父块目标/上限为 2400/3200，子块为 900/1200；这些是工程基线，不是调参后的最优值。`ContextBuilder.maxSourceChars = 12000` 仍是最终发送的字符限制。

## 3. 三层数据及不变量

| 层 | 职责 | 是否直接作为回答证据 |
| --- | --- | --- |
| 章节树 `SectionNode` | 表达目录、文件、标题及其父子关系，组织候选与摘要 | 标题和生成摘要仅用于导航；具体事实需读取原文 |
| 父块 `ParentChunk` | 有长度上限、尽量连贯的一段原文上下文 | 可以，但需要相关性与预算检查 |
| 子块 `ChildChunk` | 在父块内部形成更细的检索单元 | 可以，是正文检索的基本粒度 |

```text
书 / Markdown 文件夹
  └─ 目录 → 文件 → 章节 / 小节
       ├─ 父块 P1
       │    ├─ 子块 C1
       │    └─ 子块 C2
       └─ 父块 P2
            └─ 子块 C3
```

一章可以包含多个父块。父块不是整章的同义词；子块只有一个物理父块，章节树祖先通过关联查询获得。第一版子块不做固定重叠。

必须满足：

- 每块携带 `bookId`、`assetKey`、`indexGeneration` 和原文跨度，不能靠同名标题推断身份。
- 同一次检索中树、父块、子块来自同一已发布版本；引用必须保留版本与来源。
- 子块跨度包含于父块跨度；不跨文件，不把两个不连续区间伪装成一个连续引用。
- 每段正文恰有一个基础归属；扩展产生的重叠在最终打包时去重。
- 排序使用版本内的连续 `ordinal`；相邻关系另外受文件、正文单元及结构边界约束。

## 4. 结构解析与定位

### 4.1 统一输入

先产生带原文跨度的结构单元：标题、段落、列表项、代码、表格等。`SourceSpan` 使用 `[start, end)` 半开区间，范围中的字符直接取自同一份规范正文。

规范正文不是任意重新格式化的文本：EPUB/Markdown 使用与阅读定位一致的解析正文；PDF 使用同版本的提取文本。`unitKey` 区分章节或物理页，offset 的单位保持与对应正文一致。块额外保留原始文件 hash、解析器版本和 locator 映射；不得把 Markdown 原文件 offset 与解析正文 offset 混用。

切块时记录真实 `startOffset`、`endOffset`，正文从该跨度截取。首尾空白可以在显示时修剪，但不得据显示长度改写定位。段间空白归入相邻跨度或显式间隔，不得漏掉实际正文。

### 4.2 各格式规则

| 格式 | 结构来源 | 第一版边界 |
| --- | --- | --- |
| Markdown | 文件夹路径、文件、标题层级与解析块 | 文件隔离；父块不跨小节，单个长小节可产生多个父块 |
| EPUB | TOC、spine、锚点与正文块 | 同一正文单元内切分；目录映射失败时保留正文，不猜章节归属 |
| PDF | outline、物理页与可取得的正文结构 | 父块先按页内段落构建；章节树可跨页，不默认合并相邻页正文 |

完整树不能只复用 UI 的可跳转目录：没有目标位置的分组节点仍可保留其子节点；没有可靠结构时标记来源为 `inferred` 或 `page_fallback`，不能把固定页窗口称为真实章节。扫描页没有可索引文本时保持不可检索状态，本设计不加入 OCR。

嵌套章节的结束点为后续第一个同级或更高层级节点的起点，且不得越过父节点边界。例如：

```text
第 1 章起点 0，1.1 起点 10，1.2 起点 40，第 2 章起点 100
第 1 章范围 [0, 100)，不是 [0, 10)。
```

PDF 同页多个标题需要页内位置；缺乏精确映射时保存页级近似及精度标记，允许候选范围重叠并在引用时去重，不伪造精确文字坐标。章节自身的引言与子节正文分别归属，避免后续汇总重复计入。

## 5. 构建算法：结构约束下的顺序贪心

### 5.1 预算与计量

定义父块目标/上限 `B_parent`、子块目标/上限 `B_child`，其中子块预算小于父块预算。数值作为切块配置，在中英文、代码和 PDF 样本上评测后确定，不把此前的「300–500 字」「1200–1600 字」当已验证结论。

能够本地准确计数时使用指定 tokenizer 并记录计数器版本；否则使用明确标记的 UTF-16 字符预算或 token 估计预算，不混用单位、不声称估计是精确 token 数。检索块配置不依赖每次请求临时改变，配置变化需要新索引版本。

最终请求独立检查 Provider 输入窗口和输出预留；还需计入系统提示词、问题、历史、来源标签及引用正文。没有准确 tokenizer 时使用显式保守策略并承认估计误差；当前 `ContextBuilder.maxSourceChars = 12000` 的字符限制在代码另行变更前仍有效。

软目标用于选择切点，硬上限用于拒绝过长候选，不能只定义目标而实际仅使用上限。token 计量以候选的实际拼接表示为准，不假设片段计数可直接相加。单个不可分割字素簇已超过硬上限时，明确报错、保留旧索引且不发布新版本，不通过漏文来满足预算。

### 5.2 父块构建

```text
for each 文件 / 正文单元中的小节（原文顺序）:
    current = 空
    for each 结构单元:
        parts = 按类型拆分超预算单元，保留原文跨度
        for each part:
            if current 非空且追加 part 会超过父块上限:
                输出 current；current = 空
            追加 part 到 current
    输出剩余 current
```

边界决定优先于填满预算。短小节允许产生短父块，不为了装满跨文件或主题边界。按原文顺序追加，不使用会打乱顺序的装箱算法；此贪心策略不承诺全局最优。

示意：预算 500、段落长度 180/260/220 时，产生 440 和 220 两块；500 仅解释算法，不是生产参数。

可选的局部修复只处理末块与前一块：先尝试合规合并，否则尝试移动一个完整结构单元改善长度分布。不得越过文件、小节与结构依赖边界；不能改善时保留短块。软目标切点与尾块修复分别消融，不改变原文顺序，也不声称最优。

### 5.3 超长单元与子块

| 单元 | 优先切点 | 超预算处理 |
| --- | --- | --- |
| 正文段落 | 段落 → 句子 → 标点 / 词边界 | 最后才按安全字符边界硬切 |
| 代码块 | 完整代码块 → 可识别代码段 → 行 | 超长单行才硬切；保存语言与续段元信息 |
| 表格 | 完整表格 → 行组 → 单行内容 | 保存表头关联；显示时重附表头不改变原文跨度 |
| 列表 | 完整列表 → 列表项 → 项内句子 | 保留层级与引导语关联 |

先构建受父预算约束的父块，再在父块内部按同样的顺序策略和更小预算生成子块。子块不得越过父块。所有最终硬切均不得拆开代理对、组合字符或字素簇；边界检测不可无限向后搜索以突破硬上限。

完整结构超过上限时允许拆分，但记录续段关系；不可用「保护代码 / 表格」为由静默超预算。补入表头、标题路径等属于上下文包装，应单独标记并计入发送预算。

基础块不固定重叠，先靠定位和按需窗口扩展处理边界；若黄金集证明固定重叠有收益，再作为独立配置评测。

### 5.4 检索表示与原文分离

`sourceText` 是同版本原文跨度；`retrievalText` 是检索表示；`contextEnvelope` 是实际发送的来源标签、标题路径、必要表头与原文。第一版优先独立索引标题路径等确定性字段，再与正文候选融合；不通过在每块正文重复标题来隐式改变正文 BM25 统计。

生成说明单独标记，不伪造原文 offset。表头等包装只补足理解所需关系，不改变块跨度，且计入最终预算。相同包装可共享，原文引用始终来自 `sourceText`。

## 6. 检索算法：候选合并与父块扩展

### 6.1 候选生成

```text
明确用户范围并读取同一已发布索引版本
  ├─ 正文路径：现有词法策略 → 子块候选
  └─ 结构路径：标题 / 标题路径，后续可加摘要 → 对应原文候选
      ↓
合并候选、保留来源、去重 → 选择证据 → 按需扩展 → 预算打包
```

- 原文页码 / 明确章节定位先解析定位，不把数字直接当全库检索词；印刷页码与物理页码映射不明时不得猜测。选区、当前页与当前章不需要先经过全书树路由。
- 结构路径不能预先删除正文候选。标题独立命中时允许进入候选集，不能用「正文分 × 标题加成」将其清零，也不能在后续再次强制要求正文词面命中。结构命中不等于原文已证明答案。
- 词法统计固定在本次允许检索的完整范围内；筛选候选不改变 DF、平均长度等统计。不同检索信号保留来源，融合与权重需评测，不直接相加未经校准的异尺度分数。
- 不做每书最高分归一化后强制配额，不采用未经验证的 60% 或 0.34 门槛。对比题关注比较对象的证据覆盖，允许两侧位于同一节或同一块。
- 低置信时保留范围内的正文路径，允许补充检索或明确证据不足；不能把固定 top-3 扩到 top-6 当成覆盖保证。目录启发式只作可诊断的降权信号，不能误删用户直接指定的目录内容。

原有正文候选保留不等于最终 `Recall@K` 必然不降；合并后的排序、预算与去重仍需评测。

### 6.2 扩展选择

对每个命中的子块生成有限个候选：子块本身、同父块内的局部连续窗口、完整父块。同父范围优先；有可靠续段关系时，允许生成有限的跨父窗口，不把父块边界当成证据绝对边界。相邻窗口根据源跨度与结构确定，不使用筛选后列表下标、`sortOrder` 数值差或 id 字符串加一猜测邻块。

连续跨父窗口限同文件、同正文单元、同小节且原文连续的关系；表头、代码续段等可以记录 `header_of`、`continues`。跨页或不连续依赖使用多个带 locator 的 `SourceSpan`，不得拼成包围引用。缺乏可靠映射时不扩展；跨父关系不改变子块的物理父归属。所有关系受版本、范围、跳数、候选数量与最终预算限制，具体数值待评测。

逐步比较「新增有效上下文、尚未覆盖的比较对象、重复量、额外预算」，只接受有明确用途且仍符合预算的扩展；相关性证据不足时保留较小窗口，不因同父关系就认定整块相关。选择顺序与并列规则保持确定性，具体评分权重在评测前不固化。

典型决策：定义定位保留局部窗口；连续推导允许扩为父块；不同章节的两侧证据分别保留；父块噪声多则保留子块。不能只按命中子块数量决定合并。

### 6.3 最终打包

1. 按来源区间合并真正重叠的引用；不连续区间分别呈现，不能用包围区间伪装成连续证据。
2. 同一范围已用父块呈现时，不再重复发送它包含的子块。
3. 扩展、来源标签、表头补充全部计入预算；配额如启用，对最终引用检查，邻块追加不得绕过。
4. 优先保留问题各方面的证据。跨书多样性仅作偏好，不强塞无关书、不固定保证每个分支一条。
5. 大父块放不下时尝试已定义的较小窗口；不可静默截断后仍显示「整章 / 完整推导」。
6. 引用清单回显最终实际发送的内容和位置；空结果、预算不足、部分覆盖分别说明。

## 7. 存储与版本一致性（拟议，需 Drift 迁移）

以下是逻辑存储契约，尚未建表；确切字段、索引、约束和迁移编号在实现时同步到 `06-data-model.md`，不能把本文当成当前 schema。新实体主键使用 UUID，不将文件序号或标题用作永久主键。

| 数据 | 拟议存储 | 核心字段 / 关系 |
| --- | --- | --- |
| 索引版本 | `book_index_snapshots` | id、book_id、状态、源清单 hash、parser_version、chunker_version、配置指纹 |
| 章节树 | 独立 `book_sections` | id、snapshot_id、parent_id、asset_key、title、kind、位置 / 精度；分组节点允许无正文范围 |
| 父块 | 独立 `chunk_parents` | id、snapshot_id、section_id、asset_key、unit_key、start/end、ordinal、预算计量信息 |
| 子块 | 扩展现有 `search_chunks` 的正文行 | parent_id、snapshot_id、真实 start/end 与 locator；新增关联对其他来源类型保持兼容 |
| 结构关系 | 拟议有向关系表 | snapshot_id、两端实体、关系类型与结构依据；跨正文单元保留各自跨度 |
| 生成摘要 | 后续独立缓存表 | 目标范围、source_hash、prompt_version、生成配置、状态、原文引用 |

章节行不能以 `source_type='book_section'` 混入现有 `search_chunks`：现有 FTS 触发器与全局搜索会把它们收录。父块通常存范围，正文由同版本子块的原文片段组装；需要完整空白时保留对应源片段。不能从已经变化的磁盘原文重建旧版本父块。

发布规则：先在新版本写入树、父块与子块，完整性通过后，在事务内切换 active snapshot；读请求绑定所选版本，取消或失败不发布半成品。旧版本在活动读取 / 引用已安全处理后回收。

Markdown 文件夹用相对路径与内容指纹识别资源，不用 `fileIndex` 作稳定身份；同路径改内容也需要失效。目录导入指纹 `books.file_hash` 当前基于路径，不能当内容版本。索引版本或配置变化后，结构缓存、嵌入和摘要按依赖失效；不能只比较块数或 `updatedAt` 猜缓存有效。删除书籍清理应用索引，仍不删除用户原文件。

## 8. 总结是独立流程

普通问答找相关证据；全书总结需要覆盖全部目标正文，不能复用 top-K 检索冒充全书。

```text
目标正文 → 预算内局部摘要（保留来源）
         → 沿结构、按实际输入预算逐层合并
         → 章节 / 全书摘要与覆盖说明
```

不把 `level ≤ 1` 当长度标准，也不把固定 `fan-in = 8` 当 token 安全保证。父节点自有正文与子树贡献分开计算，避免重复总结；失败或取消保留已完成单元，最终结果说明未覆盖范围。

摘要缓存绑定内容、提示词版本与生成配置指纹，记录来源和生成模型；源或生成配置变化后的复用策略显式定义。生成摘要可以用于导航，具体事实应回到原文，不能把摘要再生出的断言当原文引用。
