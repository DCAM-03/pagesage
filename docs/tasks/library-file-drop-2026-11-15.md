# 桌面书库拖入文件直接阅读

日期：2026-11-15
状态：实现、定向回归及本地 Linux 安装完成

## 行为与边界

- Linux 与 Windows 的书库页接收外部本地文件拖放，覆盖文件管理器和提供
  本地文件 URI / 路径的聊天软件。聊天附件必须已下载；不请求聊天记录、
  下载远程附件或接收网页链接。
- PDF、EPUB、Markdown 沿原有导入管线复制到应用书库、去重和后台索引。
  单个有效文件自动打开阅读；重复文件直接打开已有书籍，不创建副本。
- 多文件批量导入并留在书库展示汇总；混入不支持文件时不自动跳走。
  文件夹继续走现有明确入口，不推测为批量书架或 Markdown 文件夹书。
- Linux 拖入时显示松开提示，离开 / 放下后消失；正在导入时给出忙碌反馈。
  不改正常书库布局，不引入新依赖，不修改源文件。
- 只在书库挂载期间启用原生接收，离开后禁用；不劫持阅读器的内部拖选。

## 实施与验证计划

1. 补齐 Linux GTK 文件 URI 拖放通道和生命周期，沿用 Windows 的路径通道。
2. 实现拖放提示、单文件自动打开、重复打开和忙碌反馈。
3. Flutter 通道及书库交互测试覆盖正常、异常、并发、离开页面与多文件；
   真实临时文件 / SQLite 验证复制及去重，避免只验证回调被调用。
4. 原生 URI 解析测试覆盖中文、空格、转义、localhost、远程 URI 与非法数据。
5. 定向回归、静态分析、离屏截图，静默构建安装并核对本地 Linux 产物。

证据目录：`.local-data/validation/library-file-drop-2026-11-15/`。
真实微信拖动、真实窗口及 Windows 设备检查单独记录，不以 widget 代替。

## 实现

- Linux 增加 GTK `text/uri-list` 接收、复制动作协商、拖入 / 拖离通知和
  本地 URI 解码；只接受本机或 localhost 的 file URI。拒绝远程地址、
  非法 UTF-8 / NUL 和过大的拖放载荷，不请求移动或删除来源文件。
- 沿用 `pagesage/window_drop` 通道；增加 `setEnabled` 控制生命周期，
  Windows 对应接入 `DragAcceptFiles` 的开关。未增加第三方依赖。
- 书库通过主题化临时叠层反馈拖入，通道过滤重复路径。导入复用真实
  `ImportUseCase`，不新建第二套复制、去重或索引逻辑。
- 单文件成功或重复时进入既有 reader 路由；多文件保留汇总。
  不支持文件按实际数量统计；单文件无法访问时直接显示具体错误。
- 异步循环每次导入前及导航前检查页面存活；离开页面不再读已释放的 ref、
  不继续导入本批剩余文件，也不跳回阅读器。已开始导入的当前文件允许完成。
