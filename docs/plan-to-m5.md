# PageSage 推进计划：收口到 M5 UX 现代化

版本：0.1  
日期：2026-07-16  
目标：从当前工作树状态出发，**按顺序把 M2 缺口 → M3 收口 → M4 发布就绪 → M5 UX 验收** 做完。  
对照：`docs/implementation-status.md`、`docs/07-roadmap.md`、`docs/08-ui-ux-redesign-plan.md`、`docs/tasks/ui-ux-modernization.md`、`docs/testing-ui-ux-checklist.md`、`AGENTS.md`。

## 0. 现状基线（2026-07-16）

| 范围 | 结论 |
| --- | --- |
| M0 / M1 | 主路径基本完成，可视为「已达标、仅修回归」 |
| M2 | 功能大体齐全；移动视图、笔记 MD、搜索/标注边角待补 |
| M3 | AI + 导出主体已有；体验与边界提示待打磨 |
| M4 | 备份/隐私/快捷键有；发布验收、性能与打包未闭环 |
| M5 | 代码里已有大量改造，**验收清单与一致性质感未闭合** |

**原则（全程不变）**

- 本地优先；AI 仅用户主动触发；不上传整书。  
- 不实现：云同步、账号、MOBI/AZW、Calibre、OCR、在线书城、DRM 绕过。  
- 文档默认中文；代码标识符英文。  
- 每阶段：小切片 + `flutter analyze` + 相关 `flutter test` + 必要手测。  
- 每阶段结束回写 `docs/implementation-status.md` 与路线图勾选。

**预估工作量（单人全职量级，仅作排期参考）**

| 阶段 | 内容 | 参考人天 |
| --- | --- | --- |
| P0 | 稳定性与已知缺陷 | 2–3 |

## 3. 阶段 P2 — 完成 M3 Beta 收口

**目标：** AI 与导出达到「可日常使用」，边界清晰。

### 任务

| ID | 任务 | 完成标准 |
| --- | --- | --- |
| P2-1 | AI 面板状态机 | 未配置 / 无 Key / 网络失败 / 取消 / 上下文过长 文案与动作完整 |

## 6. 推荐执行顺序（甘特逻辑）

```text
P0 稳定性 ──┬── P1 M2 缺口（含文件夹扫描）
            │
            ├── P2 M3 收口（可与 P1 后半重叠）
            │
            └── P3 M4 发布就绪（依赖 P0–P2 主路径稳）
                     │
                     └── P4 M5 验收与质感（依赖功能不再大改）
```

**硬依赖**

- 文件夹扫描依赖任务中心与导入用例（P1-1 前需 P0 导入意图稳定）。  
- M5 视觉冻结应在功能大改之后，避免返工。  
- 发布打包不阻塞 M5 视觉，但 M4 手测应在 M5 验收前完成一轮。

## 7. 每阶段固定节奏

1. 从本计划取 1 个切片（尽量 ≤1 天可合并的 PR 粒度）。  
2. 实现 → `dart format` → `flutter analyze` → 相关 `flutter test`。  
3. 必要手测（阅读器相关必须 EPUB+PDF 各一次）。  
4. 更新 `implementation-status.md`。  
5. 阻塞问题记入 checklist「阻塞问题」栏，不静默跳过。

## 8. 风险与缓冲

| 风险 | 缓解 |
| --- | --- |
| PDF WebView 平台差异 | P0/P1 固定样本；Windows 优先，Android 设备缺失时文档标注 |
| EPUB 复杂 TOC/CFI | 保持 href+offset 回退；坏书不崩溃 |
| 大图/生成资源膨胀 | 图标源图 1024；商店图不进 APK 可放 `docs/generated` 或 store 目录并 git 策略明确 |
| 范围膨胀 | 任何云/OCR/MOBI 需求一律拒或新开路线图版本 |
| UX「永远改不完」 | P4 以 checklist 勾完为结束，不无限抛光 |
